# Sharpa 全部 13 任务对照

本轮覆盖 ConTrack 已提供的全部 13 个 RB-Y1A / Sharpa HDF5 片段。
每个片段单独训练 BPTT 和原 PPO，共 26 个单卡任务。

- 使用 Hammer 成功版的 e3 配方，从头训练，不加载 PPO 或 XHand 策略。
- 使用已发布的 Sharpa 默认规模：6000 个并行环境，500 个 PPO 等效 iteration。
- 每项正式训练为 6000 × 500 × 16 = 48M 真实交互，seed 2026。
- 每项最终评估 4096 episodes、256 环境、seed 12345，固定每环境配额。
- 评估阈值仍为位置 0.1m / 旋转 1rad，任务输入、输出和真实奖励保持原实现。
- BPTT 的想象奖励和终止近似保持 Hammer 发布版原有设计。
- BPTT 同时报告 holdout WM 的 1/8/16/32 步关节、速度、物体位姿和接触误差。

XHand 的上一轮使用 8000 环境 / 64M 交互；本轮 Sharpa 使用 6000 环境 / 48M。
两个机器人之间不能据此作匹配交互预算的优劣结论；每个 Sharpa 任务内的 BPTT/PPO 预算一致。
本轮是单 seed 筛选，不代表多 seed 稳定性，也不等同于论文的 5000-update 正式预算。

训练核心、原任务、PPO、原训练/评估入口及配置共 76 个文件保持与 Hammer 发布版逐字节一致。
仅扩展实验调度入口以选择 Sharpa、自动推导任务总数和正确记录预算。
实验使用独立 checkout、机器人资源副本、物体 USD 缓存、节点本地编译缓存和输出目录。
使用当前 PAI-DLC 默认驱动和节点调度，不设置 Driver / AssignNodeSpec。

每项先运行短训练及策略导出评估，核对 Actor 更新、观测/奖励 parity、完整步数和策略 SHA256。
门禁失败会退出并保留异常，不会自动换配方。正式训练完成后自动评估；每小时记录进程、GPU、
iteration、reward、训练期 completion fraction、异常和预计剩余时间。最终成功率由独立评估产生。
集群监控在 26 个任务全部终止后自动退出。
